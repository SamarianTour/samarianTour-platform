DICCIONARIO DE CLASES - MODELO DE DOMINIO
Plataforma Digital para la Gestión Integrada y Sostenible del Turismo en Santa Marta
================================================================================
Versión 2 (corte 3): actualizado al código construido, rama develop, 18 de noviembre de 2026.
Cada cambio cita su decisión (DN-xx núcleo, DC-xx catálogo); ver docs/decisiones-*.md.

Convenciones de tipos
- UUID: identificador único universal (entidades del Núcleo, PostgreSQL).
- String (en id): identificador del Catálogo (MongoDB).
- Instant: momento exacto en el tiempo (marcas de tiempo).
- LocalDate: fecha de calendario sin hora.
- LocalTime: hora del día sin fecha.
- BigDecimal: porcentajes y precios de referencia del catálogo (evita errores de redondeo).
- long (montoCentavos, precioBase): dinero del núcleo en pesos o centavos enteros, sin decimales.
- Integer: entero que puede quedar vacío (null). int: entero obligatorio.
- List<X>: lista de valores de tipo X.
- [0..1] después del tipo: el atributo es opcional.
- «record»: tipo de valor inmutable (record de Java), sin identidad propia.

================================================================================
1. USUARIOS Y CUENTA
================================================================================

--------------------------------------------------------------------------------
Usuario (clase abstracta)
--------------------------------------------------------------------------------
Datos comunes de cualquier persona que usa el sistema. Es abstracta: nunca existe
un "usuario" a secas, siempre es uno de los cinco roles que heredan de ella.

Atributos
- id : UUID ............................. Identificador único del usuario.
- nombre : String ....................... Nombre registrado; se cifra en la base de datos (RF-01, DN-28).
- correo : String ....................... Correo de acceso; único en el sistema (RF-01, RF-02).
- hashContrasena : String ............... Contraseña cifrada con BCrypt; nunca se guarda en texto plano. Vacía en una cuenta interna que aún no la establece (RF-01, RF-81).
- estado : EstadoCuenta ................. ACTIVA, DESACTIVADA o SUPRIMIDA (RF-13, RF-81).
- intentosFallidos : int ................ Inicios de sesión fallidos consecutivos (RF-05).
- bloqueadaHasta : Instant [0..1] ....... Hasta cuándo está bloqueada la cuenta (15 min tras 5 fallos) (RF-05).
- fechaRegistro : Instant ............... Momento en que se creó la cuenta.

Métodos
- autenticar(contrasena : String) : boolean .. Verifica la contraseña (RF-04).
- registrarIntentoFallido() : void ...... Suma un fallo y bloquea al quinto (RF-05).
- estaBloqueada(ahora : Instant) : boolean .. Indica si el bloqueo sigue vigente (RF-05).
- debeAceptarPolitica(vigente : PoliticaDatos) : boolean .. Indica si le falta aceptar la versión vigente de la política (RF-09, RF-10).
- aceptarPolitica(politica : PoliticaDatos) : void .. Registra la aceptación de una versión (RF-10).
- cambiarNombre(nombre : String) : void .. Actualiza el nombre desde Mis datos (RF-12, DN-31).
- cambiarContrasena(hash : String) : void .. Restablece o establece la contraseña (RF-08, RF-81).
- crearInterna(rol, nombre, correo) : Usuario .. Crea una cuenta de operador, administrador o gestor sin contraseña; se establece con la invitación (RF-81, DN-40).
- desactivar() : void ................... Desactiva una cuenta interna (RF-81, DN-40).
- reactivar() : void .................... La vuelve a activar (DN-40).

Relaciones
- Es padre de Turista, Prestador, OperadorDisponibilidad, Administrador y GestorDestino.
- Compuesta por 0..* AceptacionPolitica, 0..* CodigoUnUso, 0..* Sesion y 0..1 SolicitudSupresion.

--------------------------------------------------------------------------------
Turista (hereda de Usuario)
--------------------------------------------------------------------------------
Persona que consulta el catálogo, envía solicitudes, paga y opina.

Atributos
- whatsapp : String ..................... Número de WhatsApp; se cifra (AES-256-GCM) (RF-03, RF-44, DN-28).
- whatsappVerificado : boolean .......... Si confirmó el número con el código de un solo uso (RF-03).

Métodos
- puedeEnviarSolicitudes() : boolean .... Solo con el WhatsApp verificado (RF-30).
- verificarWhatsapp() : void ............ Marca el número como verificado (RF-03).
- cambiarWhatsapp(numero : String) : void .. Cambia el número y exige verificarlo de nuevo (RF-12).
- suprimir() : void ..................... Supresión de datos (Ley 1581): anonimiza nombre, correo y WhatsApp y deja la cuenta SUPRIMIDA (RF-13, DN-31).

Relaciones
- Envía 0..* SolicitudDisponibilidad.
- Escribe 0..* Opinion (solo con una solicitud pagada de la oferta, HabilitacionOpinion).

--------------------------------------------------------------------------------
Prestador (hereda de Usuario)
--------------------------------------------------------------------------------
Persona natural o jurídica con RNT que publica ofertas. En el código los datos de la cuenta viven en el
módulo cuentas y los del RNT, el WhatsApp y el operador en el módulo prestadores (misma id).

Atributos
- numeroRnt : String .................... Número del Registro Nacional de Turismo (RF-62).
- razonSocial : String .................. Razón social; se autocompleta desde el RNT (RF-63, DN-33).
- municipio : String .................... Municipio registrado en el RNT (RF-63).
- categoriaRnt : String ................. Categoría registrada en el RNT (RF-63, DN-33).
- tipo : TipoPrestador .................. Alojamiento, restaurante, agencia operadora o guía independiente (RF-68).
- numeroEmpleados : Integer [0..1] ...... Empleados declarados; vacío si es guía independiente (RF-68).
- modalidadesGuianza : List<ModalidadGuianza> .. Solo guías: modalidades que ofrece (RF-69).
- idiomasAtencion : List<String> ........ Solo guías: idiomas en que atiende (RF-69).
- estadoRnt : EstadoRnt ................. ACTIVO, INACTIVO, NO_ENCONTRADO o VERIFICACION_PENDIENTE (RF-76).
- vistoEnRnt : boolean .................. Si el RNT lo encontró alguna vez: distingue INACTIVO de NO_ENCONTRADO (DN-36).
- ultimaSincronizacion : Instant [0..1] .. Última verificación contra el RNT (RF-73, RF-76).
- whatsapp : String ..................... WhatsApp donde recibe las notificaciones; cifrado y no público (RF-71, DN-34).
- whatsappVerificado : boolean .......... Si lo verificó con el código (RF-71, DN-33).
- codigoWhatsapp : CodigoWhatsapp [0..1] .. Código vigente para verificar el WhatsApp (DN-33).
- operador : OperadorDisponibilidad [0..1] .. Operador asignado; atiende todas sus solicitudes (RF-32, DN-39).
- habilitadoEnCatalogo : boolean ........ Lo último que se avisó al catálogo sobre su habilitación (RF-77).
- versionHabilitacion : long ............ Versión de la habilitación; el catálogo descarta avisos viejos (DC-02).
- suprimidoEn : Instant [0..1] .......... Cuándo se suprimieron sus datos (RF-13, DN-45).

Métodos
- categoria() : CategoriaPrestador ...... Guía independiente, micro y pequeño (hasta 50), mediano (51 a 200) o grande (RF-72, RF-89).
- estaHabilitado() : boolean ............ Puede publicar solo con el RNT activo (RF-79).
- sincronizar(consulta : ConsultaRnt) : void .. Actualiza estado y datos con la respuesta del RNT (RF-76, DN-36).
- verificarWhatsapp(codigo : String) : boolean .. Valida el código de 6 dígitos, con 3 intentos (RF-71, DN-33).
- asignarOperador(operador) : void ...... Cambia el operador asignado (RF-81, DN-39).
- suprimir() : void ..................... Borra datos personales y cuenta de cobro si no hay compromisos pendientes (RF-13, DN-45).

Relaciones
- Compuesto por 0..1 CodigoWhatsapp y 0..* CuentaCobro; tiene 0..1 PerfilPublico.
- Asignado a 0..1 OperadorDisponibilidad.
- Publica 0..* Oferta.
- Recibe 0..* SolicitudDisponibilidad y 0..* Dispersion.

--------------------------------------------------------------------------------
OperadorDisponibilidad (hereda de Usuario)
--------------------------------------------------------------------------------
Personal interno que atiende las solicitudes de los prestadores que tiene asignados y verifica el
cupo con el prestador fuera de la plataforma. Sin atributos propios. La asignación es estática (RF-32, DN-09).

Relaciones
- Asignado a 0..* Prestador.
- Atiende 0..* SolicitudDisponibilidad.

--------------------------------------------------------------------------------
Administrador (hereda de Usuario)
--------------------------------------------------------------------------------
Personal interno que modera, sincroniza el RNT, gestiona zonas, cuentas internas, operadores y la
comisión. Sin atributos propios.

Relaciones
- Define 0..* ConfiguracionComision.

--------------------------------------------------------------------------------
GestorDestino (hereda de Usuario)
--------------------------------------------------------------------------------
Perfil institucional de solo lectura que consulta indicadores agregados
(RF-85 a RF-89). Sin atributos propios ni relaciones.

--------------------------------------------------------------------------------
PoliticaDatos
--------------------------------------------------------------------------------
Cada versión publicada de la política de tratamiento de datos. La vigente es la
de fecha de publicación más reciente.

Atributos
- version : String ...................... Identificador de la versión, por ejemplo "v1.1"; única (RF-10).
- fechaPublicacion : LocalDate .......... Fecha en que se publicó (RF-10).
- urlTexto : String ..................... Enlace al texto completo de esa versión.

--------------------------------------------------------------------------------
AceptacionPolitica
--------------------------------------------------------------------------------
Constancia de que un usuario aceptó una versión de la política.

Atributos
- fechaAceptacion : Instant ............. Momento de la aceptación (RF-10, RNF-09).

Relaciones
- Pertenece a 1 Usuario y referencia 1 PoliticaDatos.

--------------------------------------------------------------------------------
CodigoUnUso
--------------------------------------------------------------------------------
Código temporal de un solo uso para verificar el WhatsApp del turista o para restablecer o
establecer la contraseña.

Atributos
- id : UUID ............................. Identificador del código.
- proposito : PropositoCodigo ........... Para qué sirve el código (RF-03, RF-07, RF-81).
- hashCodigo : String ................... Hash del código o del secreto del enlace; no se guarda en texto plano.
- emitidoEn : Instant ................... Momento en que se generó.
- expiraEn : Instant .................... Vencimiento: 30 minutos; 72 horas la invitación de una cuenta interna (RF-08, DN-29).
- usadoEn : Instant [0..1] .............. Momento en que se usó (RF-08).
- intentosFallidos : int ................ Intentos fallidos; al tercero el código deja de servir (DN-29).

Métodos
- esValido(ahora : Instant) : boolean ... Válido si no venció, no se ha usado y le quedan intentos (RF-08).
- usar(ahora : Instant) : void .......... Lo marca como usado.
- registrarIntentoFallido() : void ...... Suma un intento fallido (DN-29).

--------------------------------------------------------------------------------
Sesion
--------------------------------------------------------------------------------
Sesión abierta de un usuario. El token de renovación es un TokenOpaco; la sesión guarda solo el hash de su
secreto, y al renovar se rota (DN-29).

Atributos
- id : UUID ............................. Identificador de la sesión (la parte <id> del token).
- hashRenovacion : String ............... Hash del secreto del token de renovación (DN-29).
- creadaEn : Instant .................... Inicio de la sesión.
- expiraEn : Instant .................... Vencimiento del token de renovación.
- revocadaEn : Instant [0..1] ........... Cuándo se cerró la sesión (RF-06).

Métodos
- estaVigente(ahora : Instant) : boolean .. Vigente si no venció ni fue revocada.
- renovar(hash : String, ahora : Instant) : void .. Rota el secreto y extiende la vigencia (RF-04).
- revocar(ahora : Instant) : void ....... Cierra la sesión (RF-06).

Relaciones
- Pertenece a 1 Usuario; usa TokenOpaco.

--------------------------------------------------------------------------------
TokenOpaco «record»
--------------------------------------------------------------------------------
Token que se entrega al cliente con la forma <id>.<secreto>: el token de renovación y el enlace del
correo. Solo el hash del secreto se guarda (DN-29).

Atributos
- id : UUID ............................. Identificador de la sesión o del código.
- secreto : String ...................... Parte aleatoria; nunca se guarda en claro.

Métodos
- valor() : String ...................... Devuelve "<id>.<secreto>".

--------------------------------------------------------------------------------
SolicitudSupresion
--------------------------------------------------------------------------------
Petición del usuario de eliminar sus datos personales (Ley 1581).

Atributos
- id : UUID ............................. Identificador de la petición.
- fechaSolicitud : Instant .............. Constancia de cuándo se pidió (RF-13).
- estado : EstadoSupresion .............. SOLICITADA mientras espera, EJECUTADA cuando se cumplió (RF-13).
- fechaEjecucion : Instant [0..1] ....... Cuándo se ejecutó (RF-13).

2. PRESTADOR: PERFIL, VERIFICACIÓN Y COBRO
================================================================================

--------------------------------------------------------------------------------
PerfilPublico
--------------------------------------------------------------------------------
Lo que el turista ve del prestador. No incluye datos de contacto directo. Vive en el catálogo.

Atributos
- prestadorId : UUID .................... Prestador dueño del perfil; uno por prestador (DC-26).
- nombreComercial : String [0..1] ....... Nombre que ve el turista; si falta, la razón social (DC-26).
- descripcion : String .................. Presentación del prestador (RF-64).
- fotos : List<Foto> .................... Fotos del perfil (RF-64, DC-47).
- horariosAtencion : String ............. Horario general de atención (RF-64).
- sitioWeb : String ..................... Sitio web público (RF-64).
- redesSociales : List<String> .......... Enlaces a redes sociales (RF-64).

Métodos
- agregarFoto(foto : Foto) : PerfilPublico .. Agrega una foto, sin pasar del máximo (DC-47).
- quitarFoto(foto : Foto) : PerfilPublico .. Quita una foto.

--------------------------------------------------------------------------------
CodigoWhatsapp «record»
--------------------------------------------------------------------------------
Código de 6 dígitos que verifica el WhatsApp del prestador (DN-33).

Atributos
- hash : String ......................... Hash del código.
- emitidoEn : Instant ................... Cuándo se envió; vence a los 30 minutos.
- intentosFallidos : int ................ Intentos fallidos; máximo 3.

--------------------------------------------------------------------------------
CuentaCobro
--------------------------------------------------------------------------------
Cuenta donde el prestador recibe la dispersión. Se conserva el historial: cada
cambio crea una cuenta nueva y cierra la anterior.

Atributos
- id : UUID ............................. Identificador de la cuenta.
- tipo : TipoCuenta ..................... AHORROS, CORRIENTE, NEQUI o DAVIPLATA (RF-74, DN-34).
- entidad : String ...................... Banco o billetera (RF-74).
- numero : String ....................... Número de cuenta; se cifra con AES-256-GCM (RF-74, DN-34).
- titular : String ...................... Nombre del titular; se cifra (DN-34).
- vigenteDesde : Instant ................ Desde cuándo es la cuenta vigente (RF-74).
- vigenteHasta : Instant [0..1] ......... Hasta cuándo fue vigente; vacío si es la actual (RF-74).

Métodos
- esVigente() : boolean ................. Indica si es la cuenta que se usa hoy (RF-74).
- cerrar(ahora : Instant) : void ........ La cierra al registrar una nueva.

--------------------------------------------------------------------------------
Coordenada «record»
--------------------------------------------------------------------------------
Tipo de valor reutilizable para representar una ubicación.

Atributos
- latitud : double ...................... Latitud geográfica.
- longitud : double ..................... Longitud geográfica.

--------------------------------------------------------------------------------
Zona
--------------------------------------------------------------------------------
Lugar o atractivo turístico registrado por el Administrador.

Atributos
- id : String ........................... Identificador de la zona.
- nombre : String ....................... Nombre de la zona; único sin importar mayúsculas ni tildes (RF-84, DC-49).
- descripcion : String .................. Descripción (RF-84).
- ubicacion : Coordenada ................ Ubicación; la usa la recomendación para las alertas del IDEAM (RF-84, DR-15).
- areaProtegida : boolean ............... Marca de área protegida o ecosistema sensible (RF-84, RF-25).
- altaAfluencia : boolean ............... Marca de zona congestionada (RF-84, RF-29).
- activa : boolean ...................... Si la zona está activa o fue inactivada (RF-84).
- buenasPracticas : List<String> ........ Buenas prácticas ambientales (RF-25, RF-84).
- condicionesVisita : String ............ Condiciones de visita (RF-25, RF-84).

Métodos
- registrar(datos : DatosZona) : Zona ... Crea una zona (RF-84, DC-49).
- editar(datos : DatosZona) : void ...... Edita o inactiva una zona (RF-84, DC-49).

--------------------------------------------------------------------------------
Oferta
--------------------------------------------------------------------------------
Identidad estable de un servicio publicado por un prestador. Solicitudes y
opiniones apuntan aquí. Su contenido vive en sus versiones.

Atributos
- id : String ........................... Identificador fijo de la oferta.
- tipo : TipoOferta ..................... ACTIVIDAD, PAQUETE, ALOJAMIENTO o RESTAURANTE; no cambia después de creada.
- retirada : boolean .................... Si el prestador la retiró del catálogo (RF-65).
- rntPrestadorActivo : boolean .......... Copia del RNT del prestador, que llega del núcleo por aviso (DC-02, DC-03).
- versionHabilitacion : long ............ Versión del último aviso de habilitación aplicado (DC-02).

Métodos
- estaVisible() : boolean ............... Visible si tiene versión publicada, no está retirada y rntPrestadorActivo; un paquete además exige que todas sus actividades estén visibles (RF-22, RF-65, RF-77).
- editar(version : VersionOferta) : void .. Deja una versión pendiente de moderación; sigue visible la publicada (RF-66, DC-06).
- aprobar(numero : int) : void .......... Publica la versión pendiente con ese número (RF-79, DC-05).
- rechazar(numero : int, motivo : String) : void .. Rechaza la versión pendiente con su motivo (RF-79).
- retirar() : void ...................... La retira del catálogo (RF-65).

Relaciones
- Compuesta por 0..1 VersionOferta publicada y 0..1 VersionOferta pendiente (al menos una existe; publicada es null en una oferta nueva, DC-06).
- Habilitada por 1 PrestadorCatalogo.

--------------------------------------------------------------------------------
VersionOferta (clase abstracta)
--------------------------------------------------------------------------------
Contenido de la oferta en un momento dado, sujeto a moderación. La versión
publicada es la que ve el turista; la pendiente es la edición en revisión
(RF-66). En el código, los campos comunes se agrupan en ContenidoComun y los de la moderación en
RegistroModeracion (agrupación técnica; no cambia el modelo).

Atributos
- numero : int .......................... Número de la versión; la decisión de moderación lo cita (DC-05, DN-08).
- nombre : String ....................... Nombre de la oferta (RF-65).
- descripcion : String .................. Descripción (RF-20, RF-65).
- precioReferencia : BigDecimal ......... Precio informativo, no vinculante (RF-20, RF-65).
- horarios : String ..................... Texto informativo con días o franja de operación (RF-20, RF-65).
- ubicacion : Coordenada [0..1] ......... Ubicación de la oferta (RF-20, DC-19).
- comoLlegar : String ................... Indicaciones para llegar (RF-20).
- capacidadMaxima : int ................. Máximo de personas por solicitud (RF-65).
- fotos : List<Foto> .................... De 1 a 6 fotos, en orden (RF-20, RF-65, DC-39, DC-47).
- estadoModeracion : EstadoModeracion ... EN_MODERACION, APROBADA o RECHAZADA (RF-66, RF-79).
- motivoRechazo : String [0..1] ......... Motivo si el Administrador la rechazó (RF-79).
- enviadaEn : Instant ................... Cuándo se envió a moderación.
- revisadaEn : Instant [0..1] ........... Cuándo la revisó el Administrador.

Métodos
- unidadPrecio() : String ............... Abstracto: por persona, por noche y unidad o promedio por persona (RF-20).

Relaciones
- Ubicada en 1 Zona.
- Compuesta por 1..6 Foto.
- Es padre de VersionActividad, VersionPaquete, VersionAlojamiento y VersionRestaurante.

--------------------------------------------------------------------------------
VersionActividad (hereda de VersionOferta)

Atributos
- tipoActividad : TipoActividad ......... Categoría de la actividad (RF-14, RF-65).

- accesibleSillaRuedas : boolean ........ Si es accesible en silla de ruedas (RF-17).

Atributos
- turistaId : UUID ...................... Turista habilitado.
- ofertaId : String ..................... Oferta de la que puede opinar.

Relaciones
- Referencia 1 Turista y 1 Oferta.


================================================================================
4. SOLICITUD DE DISPONIBILIDAD
================================================================================

--------------------------------------------------------------------------------
SolicitudDisponibilidad
--------------------------------------------------------------------------------
Petición del turista sobre una oferta, desde su creación hasta su cierre. Se identifica por su
UUID: no tiene código corto (DN-09).

Identificación
- id : UUID ............................. Identificador; es el que ve el turista.

Datos que ingresa el turista
- fechaInicio : LocalDate ............... Fecha del servicio; mínimo 2 días después del envío (RF-30).
- personas : int ........................ Número de personas (RF-30).
- notaTurista : String [0..1] ........... Comentario opcional (RF-30).
- campos : CamposDelTipo ................ Campos propios del tipo de oferta (RF-30, DN-09).

Ciclo de vida
- estado : EstadoSolicitud .............. Estado actual entre los 9 del ciclo de vida (RF-33).
- venceEn : Instant ..................... Plazo vigente en cualquier estado abierto: 24 h para el operador; 3 h de confirmación y pago desde Atendida (RF-41, RF-55, ADR-04).
- aparteHasta : Instant [0..1] .......... Hasta cuándo el prestador guarda el cupo (RF-38, RF-39).
- intentoPagoEnCurso : boolean .......... Si hay un pago en curso; no vence mientras tanto (RF-55).
- intentosPagoFallidos : int ............ Pagos fallidos; al tercero vence (RF-58).
- creadaEn : Instant .................... Momento de envío.
- actualizadaEn : Instant ............... Último cambio.

Datos que registra el operador
- condiciones : CondicionesOfrecidas [0..1] .. Precio base, política de cancelación y nota (RF-37, RF-39, RF-42).

Copia de la oferta y del prestador al crearla (no cambia)
- oferta : DatosOfertaCopiados .......... Tipo, nombre y zona de la oferta (RF-85).
- categoriaPrestador : CategoriaPrestador .. Categoría del prestador en ese momento (RF-89, DN-41).

Métodos
- crear(...) : SolicitudDisponibilidad .. Crea la solicitud PENDIENTE con el operador asignado al prestador (RF-30, RF-32).
- atender(condiciones, aparte : boolean) : void .. Pasa a ATENDIDA (RF-37 a RF-39).
- marcarNoDisponible() : void ........... Pasa a NO_DISPONIBLE (RF-39).
- responder(decision : DecisionTurista) : void .. El turista confirma o declina las condiciones (RF-43).
- vencer(ahora : Instant) : void ........ SIN_RESPUESTA tras 24 h o VENCIDA tras las 3 h (RF-41, RF-55).
- cerrarPorRntInactivo() : void ......... Cierra una solicitud abierta cuando el RNT del prestador queda inactivo (RF-77, DN-36).
- marcarIntentoEnCurso() : void ......... Marca el pago en curso (RF-55).
- registrarPagoAprobado() : void ........ Pasa a PAGADA (RF-50).
- registrarPagoRechazado() : void ....... Pasa a PAGO_FALLIDO o, al tercer fallo, a VENCIDA (RF-58).
- esTransicionValida(a : EstadoSolicitud) : boolean .. Indica si la transición está permitida.
- proximaAVencer() : Instant ............ El plazo que vence primero (venceEn o aparteHasta).

Relaciones
- Enviada por 1 Turista; sobre 1 Oferta; dirigida a 1 Prestador.
- Atendida por 1 OperadorDisponibilidad (el asignado al prestador).
- Compuesta por 1..* TransicionSolicitud y 0..3 IntentoPago.
- Genera 0..1 Dispersion; tiene 0..* NotificacionPendiente.

Restricciones
- No puede haber dos solicitudes no terminales del mismo turista, oferta, fecha y hora (RF-31).
- El plazo de 24 h cuenta desde creadaEn; el de 3 h desde que queda Atendida.
- La asignación del operador es estática: ya no hay cola compartida, ni tomar, ni liberar (RF-32, DN-09).

--------------------------------------------------------------------------------
CamposDelTipo «record»
--------------------------------------------------------------------------------
Campos propios de cada tipo de oferta (DN-09).

Atributos
- horaSalida : LocalTime [0..1] ......... Hora de salida elegida; solo actividad y paquete (RF-30).
- horaReserva : LocalTime [0..1] ........ Hora de la mesa; solo restaurante (RF-30).
- fechaSalida : LocalDate [0..1] ........ Fecha de salida; solo alojamiento (RF-30).
- numeroUnidades : Integer [0..1] ....... Unidades pedidas; solo alojamiento (RF-30).

--------------------------------------------------------------------------------
DatosOfertaCopiados «record»
--------------------------------------------------------------------------------
Copia de la oferta al crear la solicitud; el núcleo no consulta el catálogo para mostrarla.

Atributos
- tipo : TipoOferta ..................... Tipo de la oferta (RF-85).
- nombre : String ....................... Nombre en ese momento (RF-85).
- zonaId : String ....................... Zona de la oferta (RF-85).

--------------------------------------------------------------------------------
CondicionesOfrecidas «record»
--------------------------------------------------------------------------------
Lo que el operador transmite al turista al atender.

Atributos
- precioBase : long ..................... Precio total que se cobra, en pesos (RF-37, RF-46).
- politicaCancelacion : String .......... Política de cancelación del prestador (RF-39, RF-42).
- nota : String ......................... Condiciones adicionales (RF-39, RF-42).

--------------------------------------------------------------------------------
TransicionSolicitud
--------------------------------------------------------------------------------
Registro de cada cambio de estado de una solicitud.

Atributos
- de : EstadoSolicitud [0..1] ........... Estado anterior; vacío en la primera transición.
- a : EstadoSolicitud ................... Nuevo estado (RF-88).
- en : Instant .......................... Momento del cambio (RNF-09).
- actor : ActorTransicion ............... TURISTA, OPERADOR, SISTEMA o PAGOS.
- motivo : String [0..1] ................ Razón del cambio cuando aplica.

Relaciones
- Pertenece a 1 SolicitudDisponibilidad (con orden).

--------------------------------------------------------------------------------
NotificacionPendiente
--------------------------------------------------------------------------------
Aviso de un cambio de la solicitud. Se guarda en la misma transacción del cambio de estado y lo envía
una tarea programada (DN-13).

Atributos
- id : UUID ............................. Identificador.
- canal : CanalNotificacion ............. WHATSAPP (simulado en el piloto) o PLATAFORMA (RF-34, RF-44).
- tipo : TipoNotificacion ............... Evento que se avisa (solicitud recibida, atendida, pagada, cupo liberado...).
- datos : Map<String, String> ........... Datos para armar el mensaje.
- estado : EstadoEnvio .................. PENDIENTE, ENVIADA o FALLIDA.
- intentos : int ........................ Intentos de envío.
- proximoIntento : Instant .............. Cuándo reintentar.
- enviadaEn : Instant [0..1] ............ Cuándo se envió.
- ultimoError : String [0..1] ........... Último error de envío.

Relaciones
- Sobre 1 SolicitudDisponibilidad; dirigida al turista o al operador.
- Origen: RF-34, RF-44, RF-45, RF-56.


================================================================================
5. PAGO Y DISPERSIÓN
================================================================================

--------------------------------------------------------------------------------
IntentoPago
--------------------------------------------------------------------------------
Cada intento de cobro al turista. Máximo 3 por solicitud (RF-58).

Atributos
- id : UUID ............................. Identificador del intento.
- numero : int .......................... 1, 2 o 3 (RF-58).
- referencia : String ................... Referencia única enviada a la pasarela para asociar el evento (RF-46, RF-52).
- montoCentavos : long .................. Monto cobrado en centavos; siempre el precio base (RF-46, RF-49).
- estado : EstadoIntento ................ EN_CURSO, APROBADO, RECHAZADO, ERROR o ABANDONADO (RF-50, RF-58, DN-20).
- transaccionId : String [0..1] ......... Identificador de la transacción en la pasarela (RF-52).
- creadoEn : Instant .................... Inicio del intento (RF-55).
- abandonarEn : Instant ................. Cuándo se da por abandonado si no llega resultado: 30 minutos (DN-20).
- resueltoEn : Instant [0..1] ........... Cuándo tuvo resultado.

Métodos
- aplicar(evento : EventoVerificado) : ResultadoIntento .. Aplica el resultado de un evento verificado (RF-50).
- abandonarSiCorresponde(ahora : Instant) : boolean .. Lo marca ABANDONADO si pasó abandonarEn sin resultado (DN-20).

Relaciones
- Pertenece a 1 SolicitudDisponibilidad; confirmado por 0..* EventoPasarela.

--------------------------------------------------------------------------------
EventoPasarela
--------------------------------------------------------------------------------
Cada evento recibido de la pasarela (Wompi o simulada). El webhook solo lo guarda; una tarea lo procesa
después con reintentos (RF-50, DN-21).

Atributos
- id : UUID ............................. Identificador.
- claveUnica : String ................... Identificador del evento; descarta los duplicados (RF-50).
- transaccionId : String ................ Transacción de la pasarela.
- referencia : String ................... Referencia del intento.
- estado : EstadoTransaccion ............ Resultado que informa la pasarela.
- montoCentavos : long .................. Monto informado.
- recibidoEn : Instant .................. Cuándo llegó.
- procesadoEn : Instant [0..1] .......... Cuándo se procesó.
- procesamiento : EstadoProcesamiento ... Pendiente, procesado o fallido (DN-44).
- intentosProcesamiento : int ........... Intentos de procesarlo; 5 antes de quedar fallido (DN-44).
- ultimoError : String [0..1] ........... Último error.
- siguienteIntentoEn : Instant [0..1] ... Cuándo reintentar.

Relaciones
- Confirma 0..1 IntentoPago.

--------------------------------------------------------------------------------
PagoTardio
--------------------------------------------------------------------------------
Pago aprobado que llegó cuando la solicitud ya estaba vencida, o con un monto distinto; se registra y se
avisa al administrador (RF-50, DN-22).

Atributos
- id : UUID ............................. Identificador.
- referencia : String ................... Referencia del intento.
- transaccionId : String ................ Transacción de la pasarela.
- montoCentavos : long .................. Monto pagado.
- motivo : MotivoPagoTardio ............. Solicitud vencida o monto distinto.
- registradoEn : Instant ................ Cuándo se registró.
- avisoEnviadoEn : Instant [0..1] ....... Cuándo se avisó.

Relaciones
- De 1 IntentoPago.

--------------------------------------------------------------------------------
Dispersion
--------------------------------------------------------------------------------
Transferencia al prestador del precio base menos la comisión y el costo transaccional.

Atributos
- id : UUID ............................. Identificador de la dispersión.
- liquidacion : Liquidacion ............. Montos calculados al confirmarse el pago (RF-53).
- estado : EstadoDispersion ............. PENDIENTE, EXITOSA o FALLIDA (RF-54).
- intentos : int ........................ Intentos de transferencia; 3 antes de avisar al prestador (RF-54).
- ultimaCausa : String [0..1] ........... Causa del último fallo.
- cuentaDestino : String [0..1] ......... Cuenta vigente usada, enmascarada.
- idPasarela : String [0..1] ............ Identificador de la dispersión en la pasarela (RF-54).
- creadaEn : Instant .................... Cuándo se creó.
- proximoIntento : Instant [0..1] ....... Cuándo reintentar.
- ejecutadaEn : Instant [0..1] .......... Cuándo se transfirió.
- reactivaciones : int .................. Veces que se reactivó al registrar una cuenta nueva (DN-44).

Métodos
- registrarExito(idPasarela : String, ahora : Instant) : void .. La marca EXITOSA (RF-54).
- registrarFallo(causa : String, ahora : Instant) : void .. Suma un fallo; al tercero queda FALLIDA (RF-54).
- reactivar(cuenta : String, ahora : Instant) : void .. Vuelve a PENDIENTE con la cuenta nueva (DN-44).

Relaciones
- Generada por 1 SolicitudDisponibilidad; paga a 1 Prestador; usa la CuentaCobro vigente.

--------------------------------------------------------------------------------
Liquidacion «record»
--------------------------------------------------------------------------------
Cálculo de la dispersión (RF-53).

Atributos
- montoBruto : long ..................... Precio base cobrado.
- porcentajeComision : BigDecimal ....... Porcentaje vigente al confirmarse el pago, copiado (RF-83).
- comision : long ....................... Valor de la comisión.
- costoTransaccional : long ............. Costo de la pasarela, calculado con CostoTransaccional.
- montoNeto : long ...................... Lo que recibe el prestador (RF-54).

--------------------------------------------------------------------------------
CostoTransaccional «parámetro»
--------------------------------------------------------------------------------
Costo de la pasarela; es un parámetro de configuración, no una tabla (DN-23).

Atributos
- porcentaje : BigDecimal ............... Porcentaje sobre el monto.
- fijo : long ........................... Valor fijo por transacción.
- iva : BigDecimal ...................... IVA sobre el costo.

--------------------------------------------------------------------------------
ConfiguracionComision
--------------------------------------------------------------------------------
Historial de porcentajes de comisión definidos por el Administrador; la vigente es la más reciente
(DN-23).

Atributos
- porcentaje : BigDecimal ............... Porcentaje de comisión (RF-82).
- vigenteDesde : Instant ................ Desde cuándo aplica (RF-83).

Relaciones
- Definida por 1 Administrador.
